本轮风险集中在四类：

1. **一个真实的安全绕过面**（F-1）：`allow_raw_command=true` 时，TCL 命令替换 `[...]` 可让 BLOCKED 清单与路径白名单全部失效——而 `ocd.json.example` 恰好推荐这个组合。

3. **e2e 断言强度不足**（F-5/F-6/D4-4）：约 20 段 print-only，工具丢注册或 read_only 失效不会使 e2e 变红；假后端 flash banks 缺真机 `#` 前缀，多 bank 探测零自动化。
4. **两处正确性残缝 + 文档数字漂移**：disconnect×重放竞态、watch halt 窗口 Ctrl+C 残留 halted（A-1 同类）；README/面板断言数落后一个版本周期。

## 三、发现清单

### P0

### P1（11 项）

**F-1【安全】RawCommandPolicy 首词分类可被 TCL 命令替换 `[...]` 绕过**
`RawCommandPolicy.cs:69-95` 只看每段第一个 token，不在枚举即 Passthrough；`TclRpcClient.cs:118` 原样送进 `capture { … }`。TCL 语义：参数里的 `[...]` 在头命令执行**之前**求值。
攻击链（前提 `allow_raw_command: true`——ocd.json.example:29/31 恰好与 flash_allowed_paths 一起推荐）：`run_command("mdb 0 [program C:/evil.bin]")` → head=mdb 放行 → `[program …]` 先执行 → **绕过 BLOCKED 清单 + flash_allowed_paths + flash_max_bytes**；同构变体 `[dump_image …]`（任意路径落盘）、`[exit]`（杀后端）。工具描述向模型承诺的 "BLOCKED with a redirect" 契约被打穿。
修法：最小修 = 含 `[` 的段一律不判 Passthrough（→BLOCKED）；结构修 = Passthrough 反转为已知只读命令白名单。

**F-2【功能】flash_erase_sector last=-1（默认值）下发字面量 token `last`，主线 openocd 必失败**
`FlashTools.cs:449-450`：`lastText = last == -1 ? "last" : last.ToString()` → `flash erase_sector 0 0 last`。工具描述（:431）承诺 "last may be -1 meaning 'to the end of the bank'"。e2e 假后端（:151-152）自己原样回显该串——自证闭环；该工具快乐路径单测/e2e 双层零覆盖（F-6）。代码内无 REAL-MACHINE 验证注记（对照本仓 A-9 先例的注记纪律）。
修法：从 flash_info 取 bank 扇区数换算成数字下发；或真机验证 atopenocd fork 是否支持该形态并补注记。

**F-3【正确性】disconnect 与在飞只读命令的重放竞态：显式断开后后端被"顺手拉起"**
`BackendSession.cs:104-114` 重放沿用原 `startIfNeeded`，`:294-320` StopAsync 只持 connect 闸。序列：T1 读命令在飞 → T2 disconnect（探针交还是产品明文用法）→ T1 失败入重放 → 重放 `EnsureStartedAsync` 重新拉起 openocd 占住探针。**disconnect 的核心契约（探针已交还）被静默破坏。**
修法：重放一律 `startIfNeeded:false`（重放是通道重试，不该复刻"确保后端"的旧决定）。

**F-4【正确性】watch --halt：Ctrl+C 落在 halt 命令自身窗口 → 目标残留 halted 且 exit 0**
`WatchCli.cs:185-186` 的 `halt 200` 在 try **之外**，:200-213 的 finally-resume（CancellationToken.None）覆盖不到它；`halt 200` 天然 ≥200ms，正好是取消高发窗口。A-1（v0.4.31）修的是读取窗口，halt 窗口漏了——A-1 同类残余。
修法：halt 移入 try；Ctrl+C 收尾按 halt 模式补 "target may be left halted" 提示。

**F-5【测试】e2e 约 20 段 print-only：工具丢注册 / read_only 失效不会使 e2e 变红**
`e2e_fake_backend.py:364-369` 遇 JSON-RPC error 只返回 `"<MCP error: %s>"` 从不 assert。无断言段：459-479、481-485、493-505、553-563、784-789、849-866、884-891（含 read_only=true 后 flash_write 应被拦的关键段！）、927-951。
修法：每段补 3-5 行最小断言（tools/list ⊇ 30 工具名；BLOCKED 段断言前缀；read_memory 断言值序列）。

**F-6【测试】flash_erase_sector 快乐路径双层零覆盖**
工具体 `FlashTools.cs:427-470` 无任何单测；e2e 唯一调用是 BLOCKED（print-only）；假后端写好的 erase 处理器从未被触发。唯一 DESTRUCTIVE 且默认关闸的工具，实际下发命令与输出组装零自动化——正是 F-2 能藏到今天的原因。
修法：e2e 加 `allow_flash_erase=true` 段 + 参数校验抽纯函数补 Theory。

**F-7【架构】Backend↔Tools、Backend↔Launcher 命名空间级循环依赖**
`BackendSession.cs:5`（用 Tools.Parsing）、`Tools/*→Backend`、`BackendSession.cs:30`（持 Launcher）、`OpenOcdLauncher.cs:336`（用 Backend.TrafficLog）、`BackendTools.cs:187`（只为一个 const）。单程序集能编译，但四层名义分层失去意义，拆库先得搬 Parsing/TrafficLog。
修法：Parsing/ResultTag/TrafficLog 下沉叶子命名空间（如 Ocdup.Common），纯移动。

**F-8【架构】op 字符串契约横跨 41 处调用点，与 ReplaySafeOps 白名单手工同步**
`BackendSession.cs:48-52` 手写字符串集 vs 全仓 41 处 `op: "..."` 24 种串。已出过一次真 bug（v0.4.31 前 list_breakpoints 重放从未生效，`BpTools.cs:206-207` 自述）；SvdTools 被迫传别名 `op:"read_memory"`（:134/:197），面板/流量日志归属失真。
修法：op 常量化（internal const），白名单引用同一常量；SvdTools 用真实工具名并把两个寄存器 op 显式加入白名单。

**F-9【卫生】undefined/ 是 AI 会话残留脚本区，且是 .gitignore 唯一漏网项**
`undefined/temp/` 下 7 个文件 21KB：openocd 排障日志 + r.bat/q.ps1/s.ps1 会话临时脚本（内容与 ocdup 源码零关联，路径变量取值 `undefined` 被字符串化所致，mtime 2026-10-31 22:08）。下次 `git add -A` 会连本机路径一起入库。
修法：`rm -rf undefined/` + `.gitignore` 追加 `undefined/`。

**F-10【发布】publish.cmd 无脏树检查、只跑单测、无发布后冒烟**
publish.cmd 只检测文件锁 → `dotnet test` → publish。不跑 e2e/预算/面板（CI 才有）；不检查 git 工作树干净——可发布出"仓库里不存在的版本"；无 `--version` 冒烟、不回显版本号。
修法：前置 `git status --porcelain` 非空即 abort；发布后 `publish\ocdup.exe --version` 冒烟 + 回显版本+sha。

**F-11【文档】数字漂移四处 + 一条坏命令（D5-1/2/3/6 合并）**
- README:380 `381 个单测`、:439 `414 个单测` → 实际 **424**
